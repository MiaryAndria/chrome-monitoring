Oui, il y a bien des noms précis. « Architecture en couches » est le nom général (Layered Architecture), et il existe plusieurs variantes. Mais il faut distinguer le nom de l’architecture et le découpage interne.

Les principales architectures en couches
Architecture	Découpage typique	Ton projet
3-Tier Architecture	Présentation → Métier → Données	⚠️ proche
N-Tier Architecture	Présentation → Services → Accès données → BDD	✅ très proche
Layered Architecture	plusieurs couches avec responsabilités séparées	✅
Clean Architecture	Domain → Application → Infrastructure → Presentation	possible, mais plus complexe
Onion Architecture	Domain au centre → services → infrastructure	possible
Hexagonal Architecture	Domaine/Application + Ports + Adapters	possible, mais plus complexe

Mais attention

Le terme N-Tier est surtout utilisé quand on parle de séparation en tiers pouvant être physiquement séparés. Layered Architecture / architecture en couches est souvent plus approprié pour parler de la séparation logique du code.

Donc pour ton rapport, je te conseillerais cette formulation :

Le projet adopte une architecture logicielle en couches (Layered Architecture), organisée selon une approche multicouche de type N-Tier.

Le projet utilise une architecture 3-Tier (architecture à trois couches) afin de séparer les différentes responsabilités de l'application.

React → Controller/FastAPI → Service → Repository/Model → PostgreSQL
