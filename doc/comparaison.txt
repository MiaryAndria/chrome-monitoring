Plan — Fonctionnalité de comparaison CPU / RAM entre appareils
1. Ce qui est exploitable en base (vérifié)
Specs matérielles (pour « qui est plus puissant »)
Donnée	Table / colonne	Exemple réel
Modèle CPU	t_cpu.cpu_model	13th Gen Intel(R) Core(TM) i3-1315U
Fréquence max	t_cpu.freq_max_proc (kHz)	4500000 → 4.5 GHz
Architecture	t_cpu.cpu_architecture	X64
RAM totale (spec)	t_device.ram_total (octets)	8589934592 (8 Go), 16538578944 (~16 Go)
Accès : t_device.id → t_device_cpu.id_cpu → t_cpu.id (via le relevé le plus récent). Helper existant : _get_device_cpu_info(cur, id_device) (repository/devices/devices.py).

Métriques d'usage (pour « qui consomme plus »)
Donnée	Table / colonne	Unité
Utilisation CPU	t_device_cpu.cpu_utiliser	% 0–100 (NUMERIC(5,2))
Utilisation RAM	t_device_ram.ram_utiliser	octets
RAM totale mesurée	t_device_ram.ram_total	octets
Contrainte métier importante
Les mesures sont une ligne par (id_device, date) ; chaque appareil rapporte à son propre horodatage. Donc get_*_one_date (égalité exacte) renvoie presque toujours vide → la comparaison doit se faire sur une PLAGE de dates + moyenne (choix retenu).
t_comparaison impose CHECK (id_device_a <> id_device_b) → bloque la comparaison « single » (même appareil, 2 dates). Voir §6.
Décisions validées
Granularité : plage de dates, on compare des moyennes.
Sortie : deux blocs séparés par ressource → Usage (qui consomme plus) ET Puissance (qui est plus puissant), sans les mélanger.
Persistance : oui dans t_comparaison (resultat JSONB) + t_statut_comparaison.
Pages : garder single + double.
single = un appareil sur deux dates (type Simple = id 1)
double = deux appareils sur deux dates (type Double = id 2)
Cycle de statut (t_statut)
COMMENCER(1) → EN_COURS(2) → TERMINER(3) ; en cas d'échec ECHEC(4). (Les ids 5/6/7 utilisés actuellement = CREER/MODIFIER/SUPPRIMER → incorrects, à corriger.)
